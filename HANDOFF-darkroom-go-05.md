## The forget-the-tenant decision, in one paragraph

`auth.Tenant` has unexported fields and one constructor taking a verified
`*Principal` — that half of the Rust guarantee *is* expressible in Go, and it means
an account id from a request body cannot become a tenant anywhere. The mandatory
half is not expressible, so `auth.TenantOf(r)` **panics** when there is no verified
principal, and every id-scoped handler calls it as its first statement. Not nil
(the gateway's shape, which its own comment admits costs a hand-written nil check in
the handler — the one place that will not be written). Not a zero `Tenant` with an
empty account: `InAccountTx` with `account_id = ''` matches no rows under FORCE RLS
while every write still exits 0, which is `AGENTS.md`'s "reports success and did
nothing". Not a 500 written by the accessor: that converges — the mistake becomes
documented behaviour and a test asserts the tidy error. A panic fails the test at
the missing call and drops one connection in production. Three tests hold it:
`TestAMissingTenantPanicsInsteadOfScopingToNothing`,
`TestThePanicMessageNamesTheRoute`, `TestATenantCannotBeBuiltFromAnythingButAPrincipal`.

## Deliberately NOT done, and why

1. **`Idempotency-Replayed` is not written.**
   `openapi/v1.yaml` declares the header on two responses and
   `internal/service/idempotency.go` holds the ledger, but `service.CreateUpload`
   and `CompleteUpload` do not report whether a request was a replay. Writing the
   header from a guess would tell a client "replayed" for a request that was not.
   Next packet: thread the replay fact out of the ledger.

2. **`GET /v1/assets?order=asc` is not honoured.** The Go service lists
   newest-first only; the generated params carry `Order` and this handler ignores
   it. Refusing it instead would be a 400 the document does not declare. Recorded
   in the `ListAssets` comment and below.

3. **No cross-tenant 404 test end to end.** It is asserted where it is decided —
   `internal/service`'s tests and `service.find`, which every id-scoped method
   routes through — and needs a database. `AGENTS.md` puts the behavioural half of
   tenant scoping in the `--db` tier; this packet's router is a function call away
   from those cases, so the next packet should add
   `internal/httpapi` cases that drive the router against a seeded `pgtest` schema.

4. **No `main`, no env reading, no server binding.** The packet asked for the HTTP
   surface, not a binary. `Options` takes the four dependencies and refuses to build
   without the service and the verifier.

5. **`internal/api` has no tests.** It is generated and regenerated by
   `go generate`; the drift test reads the *document* rather than the generated
   file, which is the stronger comparison. A regenerate-and-diff belongs in
   `bin/prime`'s Go tier, as it does for the gateway — that is a gate change, not a
   packet-05 change, and the gate job is the manager's.

6. **Problem bodies are marshalled from a struct, not hand-rendered.** The
   gateway hand-renders because `api.Problem` is generated and oapi-codegen writes
   fields alphabetically. `internal/problem.Problem` is hand-written in the
   document's order, so `encoding/json` gets it right.
   `TestTheProblemBodyIsInTheDocumentOrder` **is missing** — the file comment claims
   it exists and it does not. Write it: assert the raw bytes of one problem body
   start `{"type":…,"title":…,"status":…,"detail":…,"instance":…,"code":…,"trace_id":…`.

7. **chi 405 answers 404.** Deliberate: the document declares no 405 on any path,
   and "this path exists but not for this method" leaks one more bit about the
   surface. If the fleet decides a 405 with `Allow` is wanted, it is
   `problemMethodNotAllowed` and one document change.

## Known rough edges

- **`chi.Walk` does not report a shadowed route.** The third plant — registering
  `GET /v1/assets/{id}/download` directly on the probe router, which is mounted at
  `/` while `/v1/assets/{id}` arrives through the `/v1` mount — was **invisible to
  every drift test** and served as a 404. chi's param node from the other mount
  shadows it. The two plants that *are* caught (registering on the gated subrouter,
  and a fresh top-level path) prove the comparison works; this one is a chi routing
  subtlety, not a gap in the comparison. Worth a comment in `splitRoutes`.
- **`problem.Error.Status()` is 422 for `validation_failed`,** so the 413 and 400
  paths write the status themselves via `writeStatus`. Three statuses are written by
  hand in this package, each in one function, each with a comment saying why. If
  core adds `payload_too_large`, delete `writeStatus`.
- **Loopback sockets in tests.** `internal/auth` and `internal/httpapi` each stand
  up a `httptest` JWKS server. Neither the service under test nor any handler binds
  a port: every request to the router goes through `httptest.NewRecorder`, which is
  the Go spelling of `ServiceExt::oneshot`. `AGENTS.md`'s "no network in tests" needs
  a sentence about the key-set server; the reason is in both files' headers.
